The two proposed parity rules the red tests force:

- **Line-ending normalization is allowed, nothing else is.** A staged blob whose
  bytes differ from the audited working bytes only by CRLF/LF normalization
  (for a path Git declares as `text`, or under `core.autocrlf`) is accepted,
  because the repository will contain the audited text. Any other byte
  difference is rejected with a diagnostic - never silently accepted. The
  unsupported case is a real transformation: `.git/info/attributes` declares
  `u16.txt working-tree-encoding=UTF-16LE`, so `git add` stores UTF-8 while the
  file on disk (and in the audited manifest) is UTF-16LE. `.git/info/attributes`
  is repository metadata, not governed content, so the audited tree stays clean
  and only the staged bytes differ.
- **Governance bytes are compared too.** `.ai` is excluded from the governed
  manifest, so a staged `.ai/ledger.jsonl` or `.ai/config.json` needs its own
  index-versus-worktree comparison; otherwise stale evidence can be committed
  while the disk evidence that the audit saw is current.
