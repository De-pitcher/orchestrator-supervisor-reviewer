## Goal
Complete the contributor-facing repository structure and provide a stable CI success check that fails unless every existing test-matrix job succeeds.

## Constraints
- Keep the three-OS/Python 3.8-3.12 matrix and all current test/ledger/plan commands unchanged.
- Use read-only workflow permissions, bounded timeouts, cancel superseded runs, immutable verified action revisions and disabled checkout credential persistence.
- ci-required must run even on upstream failures and exit nonzero for failed/cancelled/skipped matrix results. It must never substitute success for missing tests.
- Issue forms route vulnerabilities privately; CODEOWNERS uses the actual sole maintainer. No automated release/publishing job is added.
- Require the new stable check in live protection only after its actual successful GitHub run is verified.
- Validate complete policy links/schema and actual matrix outcomes before claiming delivery.

## Do not
- Change runtime implementation, tests, package metadata/version, plan, config or matrix coverage.
- Disable failing tests, introduce privileged PR-trigger execution, merge main or publish a package/release.

## Definition of done
Contributor intake and ownership files are linked and valid; formal scoped smoke and disclosed reviews pass; current PR has green complete matrices and stable gates, with actual main protection requiring the verified gate.
