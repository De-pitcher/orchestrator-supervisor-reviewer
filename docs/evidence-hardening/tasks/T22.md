# T22: immutable command logs
id: T22
requirements: R20
depends_on:
allowed_files: scripts/osr.py, tests/test_run_logs.py
forbidden_files:
context_files: scripts/osr.py, docs/evidence-hardening/PLAN.md, docs/evidence-hardening/HANDOFF.md
verify: python -m unittest discover -s tests -p test_run_logs.py -v

## Goal
Give every command run exclusive output storage so same-label commands cannot destroy evidence.

## Inputs and context
Read save_log, run_recorded, cmd_verify, cmd_start and all save_log callers. Current save_log ignores its sequence hint and uses second-resolution timestamp plus label; cmd_verify rereads these paths later.

## Constraints
- Implement PLAN interface 1 with stdlib and Python 3.8 compatibility.
- Keep complete output for failures and timeouts. Keep log references usable by existing consumers.
- Use exclusive creation and a unique ID, not sleeps or increased clock precision alone.

## Do not
- Change command authorization, audit policy or test identity in this task.
- Remove old logs, rewrite ledger history, or mock away the exclusive-write behavior.

## Example
Two writes for T1-task at the same frozen timestamp retain first output and second output in distinct files.

## Definition of done
- Red tests reproduce overwrite; clean controls and same-label repeated/concurrent writes pass after the fix.
- Each returned digest matches that command's actual retained bytes, including failing output.
- Independent review checks downstream rereading of multiple command logs.
