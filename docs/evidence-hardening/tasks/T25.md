## Goal
Make final audit prove the current accepted file set, including legitimate later tasks, instead of trusting historical done status.

## Inputs and context
Read cmd_approve, cmd_start, cmd_verify, cmd_review, cmd_done, gate_status, requirement_rows, cmd_audit, walk_tree, fingerprint, Ledger and state persistence. Current audit does not recompute code freshness. .ai is ignored by tree scanning; bind cards explicitly.

## Constraints
- Implement PLAN interfaces 4-6 and 8. Preserve old ledger bytes and reject incomplete new evidence records.
- Write the manifest schema and acceptance algorithm in the red-test handoff before implementing. Supervisor checks it against the fixed contracts.
- Test sequential overlapping tasks and pre-start drift; rejecting all later tasks is not a valid fix.
- Add audit --check as a read-only path using the same validation logic as reporting audit.
- Test that code changed during command execution requires a new stable verification run.

## Do not
- Run test commands from audit, compare only historical per-task global fingerprints, or silently establish a new baseline after drift.
- Compare mutable context_files input_hash verbatim when that context intentionally contains edited implementation; use the defined separate card digest.
- Migrate legacy done records by claiming that an old review approved new bytes.

## Example
Complete add(a,b)=a+b; change it to a-b; audit fails. A second task that legitimately verifies and reviews a new implementation may supersede the earlier bytes and audit passes.

## Definition of done
- Modify/add/delete/config/card drift and task-ID reuse are rejected with actionable reasons.
- Clean completion, legitimate later overlapping task, ignored cache changes and read-only repeat audits have controls.
- Missing manifest or partial state/ledger write fails closed. Legacy chain verification still works.
